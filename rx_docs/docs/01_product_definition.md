# 01. RX 개인 프로젝트의 목표와 정체성

기준일: 2026-09-25 · 2026-09-14 목표를 유지하고 G5 사용자 추가 지시를 반영.  **개인 프로젝트 전환과 최상위 목표는 사용자 확정. 개념 정리와 세부 설계 방향은 이를 구체화한 작업 기준이다.**

## 1. 프로젝트 목표

**RX는 많은 이기종 로봇과 설비·공간 인프라를 공통 작업·권한·상태·결과·복구 계약으로 연결하여, 구역·마을·도시로 확장되는 환경에서 하나의 로봇 시스템처럼 효율적이고 안전하게 협업·운영하도록 만드는 개인 프로젝트다.**

출발지의 작업부터 목적지의 완료까지 이어지는 door-to-door 전체 시퀀스와, 새로운 로봇·기능·서비스를 결합할 수 있는 생태계를 지향한다. 산업 현장의 공정은 이 목표를 적용하고 검증할 수 있는 사례 중 하나다.

‘하나의 시스템처럼 운영한다’는 것은 요청한 일이 여러 로봇과 시설을 거쳐도 작업의 연결, 현재 책임, 완료 근거와 복구 상태를 추적할 수 있다는 뜻이다. 서로 다른 장비의 실제 능력·제약과 현장별 책임을 공통 계약으로 표현한다.

## 2. 이번에 확정한 방향

| ID | 사용자 요구 | 프로젝트에 반영하는 기준 |
|---|---|---|
| PG01 | rx_ws를 개인 프로젝트로 전환 | 이후 목표와 우선순위는 개인 프로젝트 기준으로 정함 |
| PG02 | 산업 현장에 한정하지 않음 | 제조 용어와 특정 공장 조건을 범용 코어의 전제로 삼지 않음 |
| PG03 | 많은 이기종 로봇을 효율적이고 안전하게 관리 | 협업·자원 사용·실행 권한·결과·복구를 함께 다룸 |
| PG04 | 구역·마을·도시 단위까지 확장 | 장비 수, 공간, 운영 주체, 통신 조건의 확장을 목표에 포함 |
| PG05 | door-to-door 전체 시퀀스 대응 | 여러 로봇·설비에 걸친 작업 수행과 인계의 연속성을 다룸 |
| PG06 | 생태계 확장성 | 새 장비·능력·작업·서비스를 기존 체계에 연결하고 조합 |
| PG07 | RX Client Libraries와 ROBOTIS 다섯 프로젝트의 기본 전체 개발 번들 | 공통 계약은 제조사 중립으로 유지하고, 선정 버전의 다섯 제품·필수 의존성·어댑터·프로파일·예제를 순차 통합·검증 |

로봇 수·면적·처리량·지연의 수치 목표, 첫 비산업 실증 장소와 장비, 사업화 방식은 아직 정하지 않았다. 세 저장소는 사용자가 공개로 전환했다. 프로젝트 원본은 Apache License 2.0으로 제공한다. 제삼자 구성 요소의 라이선스는 각 고지를 따른다.

## 3. 핵심 개념의 작업 정의

다음은 목표를 설명하기 위한 개념이다. 현재 API·스키마 이름이나 구현 완료 기능을 새로 선언하는 표가 아니다.

| 개념 | 의미 | 예 |
|---|---|---|
| 서비스 요청 | 이용자가 달성하려는 최종 결과 | 물품을 출발지에서 수령 장소까지 전달 |
| 작업 흐름 | 결과에 도달하는 순서·조건·분기·병행·복구 | 집하, 운송, 출입, 인계, 수령 확인 |
| 능력과 작업 계약 | 참여자가 수행할 수 있는 일과 성립 조건 | 운반 하중, 출입 조건, 완료 관측 |
| 참여자 | 작업이나 인프라 기능을 제공하는 연결 대상 | 로봇, 기존 fleet manager, 문·엘리베이터 제어기 |
| 자원 | 사용·점유·인계 조건을 관리하는 대상 | 물품, 통로 구간, 충전기, 적재 공간 |
| 운영 영역 | 실행 책임과 정책이 적용되는 범위 | 로봇군, 건물, 캠퍼스의 관리 구역 |
| 작업 인계 | 다음 수행 주체로 넘길 때 확인할 책임과 근거 | 물품 보유, 수령 가능 상태, 작업 수락 |

사람의 개입·수령·복구 조치도 작업 흐름에 포함할 수 있다. 사람의 선언과 장비 관측은 각 출처와 확인 범위를 구별한다.

## 4. 대표 시나리오: door-to-door

**출발지 물품 준비 → 실내 로봇 집하 → 건물 출입 → 실외 로봇 운송 → 목적지 건물 진입 → 실내 이동·엘리베이터 이용 → 문 앞 인도·수령 확인**

이 흐름은 목표를 구체화하는 참조 시나리오다. 실제 서비스가 약속하는 완료 지점과 조건을 정하고 필요한 참여자를 연결한다. 모든 로봇과 시설 제어기를 직접 개발한다는 요구는 아니다.

각 인계 지점에서는 다음을 표현할 수 있어야 한다.

- 어떤 물품과 작업이 이동하며 현재 책임 주체가 누구인지.
- 다음 참여자가 필요한 능력·권한·자원을 확보했는지.
- 요청 접수, 실제 전달, 인수 확인과 전체 완료를 어떤 근거로 구분하는지.
- 응답 유실·인계 지연·자원 경합·로봇 고장 때 무엇이 미결이며 누가 후속 조치를 맡는지.

배송은 첫 설명 사례다. 같은 개념을 운반·청소·점검·시설 서비스·제조 등의 서로 다른 작업에 적용할 수 있는지 검증한다.

## 5. 기존 구조에서 이어가는 자산

ROS 비의존 Rust 코어·작업 의미·판정·권한·기록을 맡는 `rx-platform`과 장비 연동·실행기·앱·적용 패키지를 맡는 `rx-solutions`의 경계를 출발점으로 유지한다. 현재 두 소프트웨어 저장소와 두 이미지 구성을 즉시 변경하지 않는다.

작업 식별, 접수와 완료의 구분, UNKNOWN 보존, 영속 전달 기록, 권한 세대, 결과 확정과 자원 인계의 분리, 개입 후 재확인 규칙을 재사용 대상으로 삼는다. 새 적용 분야에서도 의미가 성립하는지 확인하고 부족한 부분은 영향과 호환성을 검토해 확장한다.

장비별 능력·검증·권한은 [장비 지원 정책](13_device_support_matrix.md)에 따른다. 2026-09-25 사용자 추가 지시에 따라 기본 전체 개발 번들의 목표는 DYNAMIXEL SDK, DYNAMIXEL Hardware Interface, AI Worker, AI Sapiens, OpenMANIPULATOR와 필요한 의존성·RX 어댑터·프로파일·예제를 모두 포함하는 것으로 바뀌었다. 이전의 제조사 기본 포함 의무가 없다는 문장은 이 요구에 한해 대체된다. 공통 계약은 특정 제조사·모델에 종속시키지 않는다. 이 목표는 설치·연결·검증 완료 선언이 아니며, G5.1은 로봇을 연결하지 않는다. [G5.1 범위](40_strict_wire_and_clients.md)와 [G5.2 모의 Ping 및 나머지 필수 통합](41_dynamixel_ping_adapter.md)을 따른다. 기존 조사·지원표·시험 근거는 [과거 기록](../references/README.md)에서 원래 범위로 보존한다.

## 6. 규모 확장에 대한 설계 방향

**각 운영 영역의 실행 책임을 유지하면서 영역 사이의 작업·자원·책임 인계를 연결하는 방향을 우선 검토한다.** 이는 목표에서 도출한 설계 제안이며 분산 프로토콜이나 배포 구성의 확정을 뜻하지 않는다.

작업 배정·자원 조정과 현장 실행의 책임을 나누고, 영역 간 신뢰·권한 위임·통신 단절·부분 장애·관측 신선도를 명세해야 한다. 현재 단일 Runtime의 규칙을 검토 없이 도시 전체에 확대 적용하지 않는다.

효율성은 완료량·대기·이동·에너지·운영 부담으로, 안전한 협업은 자원 경합·실행 권한·관측·개입·물리 보호의 책임과 검증으로 구체화한다. 측정 기준은 [02 가치와 평가](02_value_and_business.md), 현재와 목표의 경계는 [03 범위](03_product_scope.md)를 따른다.

## 7. 현재 상태와 이전 목표의 관계

구현 초안 v0.1은 2026-09-13에 마감됐다. 확인된 범위는 [초안 인계](implementation/draft_handoff.md)의 모의 셀 운전과 해당 장애 시나리오다. 다중 운영 영역, 실제 door-to-door 서비스와 도시 규모 운영은 후속 설계·구현·실증 대상이다.

공장 납품, 레이저 소재 공급, 인건비 절감과 납품 수익성은 기존 산업 적용 사례의 목표·측정 자료로 보존한다. 이 항목들을 개인 프로젝트 전체의 목적이나 모든 후속 연구의 선행 조건으로 사용하지 않는다.

이 문서는 이후 **목적·정체성·우선순위**에서 이전 산업 제품 정의보다 우선한다. 계약 v1.0의 적용 범위와 작업 의미는 유지하고 제조사 중립 문서 개정은 별도 revision과 manifest로 기록한다. 현재 저장소 구성 변경의 검증과 이전 런타임 시험 근거를 구별한다.

이전 정의는 [전환 전 기록](../references/README.md)에 보존했다. 별도의 미확정 설계 초안은 이번 결정으로 승인하거나 수정하지 않았다.
