# 07. 후속 구현과 검증

다음 구현은 [참조 인계 사례](03_product_scope.md)의 구체적 범위를 고르고 기존 계약과 대조하는 데서 시작한다. 과거 산업 셀의 모든 미결을 비산업 연구의 필수 선행 조건으로 묶지 않는다.

| 검증 층 | 검증할 주장 | 필요한 기록 |
|---|---|---|
| 문서·정적 검사 | 경계·링크·규범 hash·지원 정책의 일관성 | revision과 실제 검사 결과 |
| 단위·계약 시험 | key·CAS·상태·권한·프로토콜 의미 | 실행 commit·명령·환경·결과 |
| 통합 모의 시험 | 실제 프로세스 사이의 전달·유실·복구 | fixture 구성·원장·effect 수·실패 근거 |
| 실물 연동 시험 | 관측·제어권·정지·지지·lifecycle | 설치 개체·profile·교정·측정·한계 |
| 운영·규모 시험 | 완료율·대기·복구·부하·단절 | 작업량·참여자·환경·비교 조건 |

CI 통과는 해당 자동 검사 범위의 증거다. 이를 현장 승인·기능안전 인증·도시 규모 운영 검증으로 표시하지 않는다. 결과 불명이나 거부를 집계에서 제외해 성공률을 높이지 않는다.

새 증거는 기존 파일을 덮어쓰지 않고 별도 위치에 남긴다. 과거 기록은 [고정 원본](../references/README.md), 현재 미결은 [미결 목록](implementation/critical_open_items.md)을 따른다.
