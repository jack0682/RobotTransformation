# RX 0.4.0-rc.1 — 개발·모의 검증 배포

2026-09-30. 이 버전은 상주 프레임워크의 개발·검증용 사전 릴리스다.
Phase 2 전체 완료, 실물 운전 자격, 장기 운영 안정성을 선언하지 않는다.

## 포함 범위

- Platform의 재시작 후 복귀, 명시적 Run 폐기, 복원 전 제한 출처 추적,
  활성 Run 인덱스와 저장 조회 개선.
- 나중에 설치된 셀에도 관련 개입 사건을 적용하는 admission 수정과
  짧은 writer 포화에 대한 watchdog 처리.
- Python 장비 스킬 패키지·Host binding 변경 경로와 개발용 실행 도구.
- Linux amd64 설치 묶음: Platform, Host, BT Executor, 운영 UI, 패키지 도구,
  supervisor 실행 파일 및 고정된 소스. 실제 모의 실행 구성은 독립 P/Host/Executor다.
- 바이너리 묶음은 Python 3.11 이상과 Linux Docker Engine으로 설치하며,
  첫 설치에 컴파일이나 이미지 다운로드가 필요하지 않다.

세 저장소의 동일한 `v0.4.0-rc.1` 태그가 릴리스 기준이다. 설치 파일은
rx-solutions의 GitHub Release에 게시한다. `bundle.json`은 실제 Platform과
Solutions 커밋, 파일 해시, 이미지 ID, 아키텍처를 기록한다. 서로 다른 버전의
이미지·SDK·검증 기록을 조합해서 같은 릴리스의 증거로 사용하지 않는다.

## 설치 파일 공개 전 확인

1. 세 저장소의 main 승격 PR에서 서명·DCO와 필수 CI가 통과한다.
2. Platform 원본과 Solutions SDK 사본의 일치를 확인한다.
3. 릴리스 커밋으로 이미지를 빌드하고 이미지 내부 소스 목록을 대조한다.
4. 새 디렉터리에서 바이너리 설치와 전체 FILE_SIMULATION 검증을 수행한다.
5. 공정 작성·검토·실행, 원 요청 복구와 독립 실행 기록을 대조한다.
6. 대화형 세션에서 상태 조회·작업 반복과 15분 관찰을 수행하고,
   세 프로세스의 예기치 않은 종료·API 실패·추가 실행 여부를 기록한다.
7. 명시적 종료 뒤 서비스 종료 코드와 데이터 보존을 확인한다.

릴리스 태그를 만들었다는 사실만으로 설치 파일 공개 조건이 충족되지는 않는다.
실제 실행한 결과·아키텍처·기간·한계는 설치 파일과 함께 올리는 검증 보고서가
명시한다. Mac의 Linux amd64 에뮬레이션 결과를 Ubuntu 실기기 시험으로 표현하지 않는다.
15분 관찰은 초기 회귀 확인이며 24시간 soak 또는 현장 가용성의 증거가 아니다.

## 알려진 한계

- 실물 장비와 첫 현장 셀은 NOT_COMMISSIONED다.
- 백업 rollback 후 Host 최대값보다 높은 권한 세대를 재설정하는 OI11/OI17
  계약, 개입 사건의 전체 재개 경로, 일부 공개 RPC·스트림과 범용 플러그인 모델은 미완이다.
- 전체 ROBOTIS/ROS 번들, supervisor가 직접 관리하는 P/Host/Executor 구성,
  브라우저 조작 시험은 이 설치 파일의 검증 범위가 아니다.
- 제품 서명키 보관 체계와 오프라인 폐기 정보의 최신성은 별도 미결이다.
  설치 파일 체크섬은 바이트 일치 확인이며 독립적인 발행자 인증을 대신하지 않는다.
- 새 실행은 새 모의 세션을 만든다. 기존 원장 재초기화, 버전 간 자동 migration,
  중단된 작업의 자동 재실행은 제공하지 않는다.

## 실패·회귀 시 대응

설치 또는 검증 실패, 예기치 않은 서비스 종료, 원 요청의 중복 실행,
확정되지 않은 종료가 나오면 설치 자산을 공개하지 않는다. 이미 공개한 자산에서
재현되면 배포 안내를 중단하고 릴리스에 알려진 문제를 명시한다. 태그나 과거
바이너리를 다른 내용으로 덮어쓰지 않고 후속 버전으로 수정한다.

기존 세션의 상태 디렉터리·Docker 볼륨·증거를 보존한다. 이전 버전을 사용할 때도
이전 데이터에 임의로 연결하거나 물리 작업을 재생하지 않고 별도 설치를 사용한다.

## 보존한 연구 브랜치

`rx-platform/codex/rx-recovery-closure`,
`rx-solutions/codex/rx-program-inputs`, `rx_docs/codex/rx-program-inputs`의
기존 WIP 커밋은 원격 보존 목적이다. 이 브랜치의 원본 설명인 “backup, not for merge”를
유지하며, 그 전체를 이번 릴리스에 병합하거나 검증된 기능으로 승격하지 않는다.
