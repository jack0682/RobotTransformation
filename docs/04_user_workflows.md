# 04. 역할별 작업 흐름

목표 시나리오는 여러 로봇과 시설이 물품을 출발지에서 수령 장소까지 인계하는 서비스다. 이 문서는 목표 흐름을 정의하며 현재 UI·API의 전체 구현 완료를 뜻하지 않는다.

| 역할 | 입력·행동 | 확인해야 할 결과 |
|---|---|---|
| 이용자 | 출발지·목적지·물품·완료 조건으로 요청 | 접수·진행·최종 완료 또는 미결의 구분 |
| 서비스 설계자 | 기능·순서·분기·병행·인계·실패 경로 구성 | 각 단계의 조건과 전체 완료 근거 |
| 장비 연동자 | 능력·관측·제어권·중단·복구 profile 제공 | 실제 장비 구성과 profile의 적합 |
| 운영자 | 유효한 범위에서 시작, 상태 확인, 개입 | 누구의 권한으로 무엇을 실행했는지 추적 |
| 복구 담당 | 원래 작업·물품·잔류 명령·근거 조사 | 결과 처분과 자원 인계, 명시적 새 시작 |
| 검증 담당 | 구성·시험·미결·제약 검토 | 주장한 범위와 실제 증거의 일치 |

정상 흐름은 `요청 → 적합한 참여자·자원 확인 → 기록된 허가 → 단계 실행 → 인계 확인 → 최종 완료`다. 물품을 내려놓음, 다음 로봇이 인수함, 이용자가 수령함은 각각 필요한 경우 별도 사건이다.

응답이 사라지면 같은 요청 식별자로 원래 기록을 조회한다. 새로운 요청을 만들어 물리 작업을 자동 반복하지 않는다. 취소 요청 수락과 실제 중단·물품 지지·자원 반환을 구별한다.

사람의 확인은 actor·범위·근거와 함께 기록한다. 알림 확인만으로 접근 허가나 안전 reset을 대신하지 않는다. 실제 화면과 미지원 구간은 [구현 상태](implementation/draft_handoff.md)를 따른다.
