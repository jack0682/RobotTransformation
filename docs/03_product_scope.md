# 03. 개인 프로젝트의 범위와 검증 단계

기준일: 2026-09-14 · 목표는 [01 프로젝트 정의](01_product_definition.md)를 따른다. 아래 서비스 확장 단계와 첫 검증 구성은 제안이며 현재 구현 완료를 뜻하지 않는다.

## 1. 목표에 포함하는 범위

| 영역 | 다룰 책임 |
|---|---|
| 이기종 연결 | 로봇·기존 운영 시스템·시설의 기능·제약·관측을 공통 계약으로 연결 |
| 전체 작업 흐름 | 여러 참여자에 걸친 순서·분기·병행·인계·중단·복구 |
| 작업 배정과 협업 | 능력·준비·위치·자원·정책에 따른 수행 주체 선택과 조정 |
| 실행 의미와 권한 | 작업 동일성, 현재 실행 권한, 접수·완료·불명과 결과 근거 |
| 공유 자원 | 물품·통로·출입·엘리베이터·충전 등의 사용 조건과 인계 |
| 운영 영역 간 연결 | 영역별 책임·정책·신뢰와 영역을 넘는 작업의 연속성 |
| 운영·진단 | 전체·부분 작업 상태, 개입·복구·변경·이력 |
| 개발·확장 | 어댑터, 능력·환경 패키지, 서비스 정의, 적합성 시험과 재사용 |
| 규모 검증 | 장비·동시 작업·공간·운영 주체 증가에 따른 성능과 장애 영향 |

교통 조정·지도·주행·조작·배차의 세부 기능은 기존 소프트웨어 활용과 직접 구현을 비교한 뒤 책임을 배치한다.

## 2. 현재 기반과 확장 목표

| 항목 | 현재 확인된 위치 | 후속에 필요한 것 |
|---|---|---|
| 코어·Host·실행기·앱 | 초안 v0.1과 모의 셀 연결 경로 | 비산업 작업에 의미·결합을 적용해 검증 |
| 권한·기록·완료·인계 | 기존 계약과 해당 구현·모의 시험 | 실제 장비 근거, 미결 처리와 운영 복귀 |
| 운영 범위 | 같은 주 컴퓨터의 단일 권위 Runtime·Host가 계약 v1.0 범위 | 여러 운영 영역·단절·권한 인계의 추가 계약 |
| 실제 장비 지원 | Host·어댑터 연동 초안과 과거 산업 장비 자료 | 모델별 제어권·관측·동작 검증 |
| door-to-door | 대표 목표 시나리오 | 참여자·인계·최종 완료 조건과 연결 경로 |
| 마을·도시 규모 | 장기 목표 | 수치 요구, 배치 구조, 부하·장애·운영 실증 |

구현 범위는 [초안 인계](implementation/draft_handoff.md), 미완료 기능은 [핵심 미결](implementation/critical_open_items.md)을 따른다. 모의 셀 검증을 새로운 서비스나 분산 환경의 검증으로 확대하지 않는다.

## 3. 검증 단계 제안

| 단계 | 확인할 것 | 다음 판단에 필요한 근거 |
|---|---|---|
| P1 최소 비산업 작업 | 서로 다른 역할의 참여자가 물품 하나를 인계하며 작업을 끝냄 | 같은 작업의 접수·인계·완료·불명·복구 추적 |
| P2 실제 연결 | 접근 가능한 장비·시설과 계약 대조 | 실제 제어권·관측·인계, 정상·이상·재개 기록 |
| P3 한 구역 협업 | 여러 동시 작업과 공유 자원 조정 | 대기·경합·배정·운영 개입 측정 |
| P4 여러 운영 영역 | 서로 다른 책임 영역 사이 작업 인계 | 신뢰·권한·부분 장애·단절 후 조정 검증 |
| P5 규모 확대 | 더 많은 로봇·서비스·공간·운영 주체 | 지원 규모와 조건, 병목·복구·운영 비용 실측 |

첫 검증 후보는 **로봇 역할 A의 물품 전달 → 인계 지점 확인 → 로봇 역할 B의 수령·목적지 전달**이다. 초기에는 모의 참여자로 표현할 수 있고, 같은 계약을 적용할 수 있는 실제 장비를 선택해 대조한다. 장비·시설은 미정이며 제조 셀의 미확정 입력을 비산업 검증의 선행 조건으로 두지 않는다.

고정 출시 일정은 정하지 않는다. 작은 경로에서 확인한 변경 원인과 문제를 다음 설계에 반영한다.

## 4. 재사용과 추가 설계의 경계

현재 Rust 코어, platform/solutions 경계, 두 이미지, 기존 연동과 시험 자산을 유지한다. 규범 변경은 revision·호환 영향·manifest를 함께 기록한다. 이번 제조사 중립 개정은 장비 포함 정책과 적용 예시를 바꾸며 작업 의미·wire 구조를 유지한다.

Cell 타입의 일괄 개명이나 단일 writer를 분산 합의로 교체하는 결정을 하지 않는다. 기존 타입으로 표현할 수 있는 범위와 추가 의미를 대조하고, 필요하면 revision·호환성·검증 계획을 만든다.

장비 패키지와 전이 의존성은 필요한 profile별로 선택한다. 공통 계약은 특정 제조사에 종속시키지 않는다. 예외로, 2026-09-25 사용자 결정(PG07)에 따라 RX Client Libraries와 ROBOTIS 다섯 프로젝트는 기본 개발 번들에 포함한다. 이는 설치·검증 완료 선언이 아니다. 새 적용 분야의 장비 후보·지원 등급·구현 순서는 실제 요구와 근거로 정한다.

## 5. 지원과 서비스 완료의 선언

지원은 모델·제어기·firmware·SDK/ROS·OS/CPU·어댑터·프로파일·작업 범위·검증 결과를 묶어 선언한다. 시설과 기존 fleet manager에도 확인 가능한 명령·관측·중단·인계 범위를 적는다.

서비스 완료는 약속한 최종 조건으로 정의한다. 목적지 도착, 물품 내려놓기, 다음 참여자의 인수, 이용자의 수령 확인은 필요한 경우 각각 다른 사건으로 남긴다. 부분 작업 성공만으로 전체 서비스를 완료 처리하지 않는다.

## 6. 아직 결정하지 않은 범위

- 로봇 대수, 동시 작업 수, 처리량·지연·면적·운영 기간의 수치 목표.
- 첫 실제 로봇·시설·운영 장소와 최종 수령 조건.
- 영역 간 배정·예약·권한 위임·신뢰·통신 단절 정책과 분산 배포 구조.
- 교통·지도·주행·조작 도구 선택과 직접 개발 범위.
- 외부 참여·서비스 제공과 사업화 방식. 세 저장소는 공개되었고 프로젝트 원본의 Apache License 2.0 적용이 확정됐다.

현재 repository foundation 변경으로도 도시 전체의 실시간 통합 제어, 모든 장비 동시 지원, 자동복구 전 범위, 안전 PLC 대체나 물리 동작 exactly-once를 현재 보장으로 추가하지 않는다.

## 7. 산업 사례와 과거 기록

이전 산업 설비의 PLC·소재 공급·지그·그리퍼와 인건비 분석은 당시 적용 자료로 보존한다. 첫 물리 레이저 셀의 NOT_COMMISSIONED 상태와 기존 미결은 유지한다. 이후 첫 실증 대상을 그 셀로 고정하지 않는다.

기존 단계와 장비표는 [전환 전 범위 문서](https://github.com/jack0682/rx_docs/blob/6111a7d1dcf33052f38c3e67c6585aec2b44df3c/docs/03_product_scope.md)에 남겼다. 현재 04–19는 개인 프로젝트 목표에 맞춘 안내이며 규범의 적용 범위와 후속 제안을 구별한다.
