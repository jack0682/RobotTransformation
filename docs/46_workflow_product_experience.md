# Workflow 제품 경험의 목표

기준일: 2026-10-01. 사용자가 커넥터팀에서 받은 `Workflow_v1.1.html`을 제시하며
“이 기능들이 되었으면 좋겠어, 이게 내 워너비야”라고 지정했다.
이 문서는 그 **기능과 작업 흐름을 RX의 제품 목표에 반영**한다. 화면의 모든 세부 정책을
이미 검증된 실행 계약으로 승인했다는 뜻은 아니다. 기존 [제품 목표](01_product_definition.md)와
[상주 프레임워크 완료 원장](implementation/resident_framework_completion.md)의 전체 범위를 유지한다.

사용자 재강조: UI를 강조하는 이유는 미감 자체가 아니라 **참조 HTML의 초안 기능 전체가 원하는
제품 기능이기 때문**이다. 액션 그래프를 메인 인터페이스로 두되, 캔버스 면적·배치·색상 개선이나
노드 이동/저장만으로 해당 목표를 달성했다고 취급하지 않는다. Task/Context/Property 계약,
Object/Resource 모델, 값의 결정과 출처, Constraint, Capability/Skill 매핑, Handoff, 실행 정책,
Preview와 게시/운영의 연결까지 기능별 실제 동작으로 확인한다.

기능 완료의 단위는 **화면 조작 → 서버의 버전 있는 자료 → 실제 계산/검증 → 지원되는 실행·추적
결과**다. 예를 들어 품목·형·작업면을 바꾸면 맞는 지그·툴링 조건과 실행값이 재검토되고, 싱글/듀얼
구성에 따라 동시 파지 가능성과 교환 순서가 달라져야 한다. 회전 정렬 장비는 별도 참여자이며,
그 준비/점유/완료 조건도 검사 대상이다. 모의 구현과 실제 장비 근거는 구별한다.

참조 원본 SHA-256: `8ee2b0738100c5c1b764a6fdb74f8651e47dd1b24bd81018859964ea71d3d54e`.
원본은 사용자 제공 자료로 보존하며 여기에는 원본 코드·브랜드·현장 데이터를 복제하지 않는다.

## 사용자가 얻게 될 경험

사용자는 재사용 가능한 Task를 배치하고 대상 물체·현장 자원을 선택한다. RX는 적용할 실행값과
그 출처를 보여주고, 제약과 필요한 능력을 대조해 로봇 후보를 설명한다. 사용자는 조건·병렬·반복·
인계를 연결하고 검증 오류를 해당 위치에서 고친 뒤, 같은 버전의 흐름을 모의 실행·검토·배포·운영한다.

개발자는 Task/Skill/장비 연결과 데이터 계약을 정의하고, 운영 담당자는 그 범위에서 현장별
대상·자원·정책을 조합한다. 일반 작업에서 임의 JSON, 포트 번호 또는 내부 권한 타입을 직접
다루게 하는 것을 최종 사용자 경험으로 삼지 않는다.

완료 상태를 꾸며내지 않는다. 이 참조의 실질적인 상호작용 범위는 Workflows/Definitions다.

## 참조에서 유지할 경험과 실제 제품에서 연결할 책임

- **유지:** 라이브러리–캔버스–설정 패널, Task 설정 후 Robot 적합성 확인, 계산값의 출처 표시,
  사용자/개발자 작업 분리, 오류 위치로 이동, 대상 그룹, 포트별 경로, 버전 구분.
- **실제 저장:** 참조의 데이터는 페이지 메모리 변수에 있고 영속 저장 호출이 없다. RX의 기존
  초안 버전·원 요청·충돌 처리에 연결해 새로고침·재로그인 이후에도 유지한다.
- **규칙 실행:** 참조의 규칙 목록 편집과 일부 하드코딩 계산이 분리돼 있다. 제품은 표시한
  규칙 버전이 실제 계산에 쓰였는지 입증하고, 값 누락·단위·유형 범위·순환 상속을 명시적으로 다룬다.
- **그래프 의미:** 참조의 I/O 링크 편집과 `runSim`의 `w.order` 순회가 분리돼 있다. RX의 Preview와
  실행은 화면의 실제 연결·조건·합류·반복 의미를 따라야 한다. 현재 지원하지 않는 의미를 조용히 직렬화하거나 축소하지 않는다.
- **게시와 운전:** 참조의 게시 동작은 메모리의 상태/버전 변경이고 Preview 인계 성공은 예시 로그다.
  RX는 버전 게시, 설치 적용, 실행 허가, 실제 수행·인계 결과를 구분해 연결한다.
- **실패 처리:** 실행 실패가 확인된 경우의 Retry와 응답 유실로 결과가 불명인 경우를 구분한다.
  UNKNOWN에서 물리 명령을 새 요청으로 반복하거나 UI의 재할당 선택으로 기존 점유를 지우지 않는다.

## 보이는 결과물을 만드는 구현 순서

이는 전체 목표를 작은 데모로 줄이는 단계 구분이 아니다. WF01–WF17과 RF01–RF14는 모두 유지하고,
각 단계가 끝날 때 직접 사용할 수 있는 화면과 실제 데이터의 왕복을 제공한다.

1. **실제 저장되는 설계 작업대:** 기존 초안/버전 API를 중심으로 라이브러리·캔버스·설정 패널을
   연결한다. 추가·연결·수정·오류 이동·저장·재열기를 먼저 눈으로 검증한다.
2. **대상과 실행값이 연결되는 작업대:** Task/Object/Resource/Property 계약, 대상 그룹,
   계산 근거·제약·로봇 후보·Skill 매핑을 같은 문서와 버전으로 연결한다.
3. **그림과 같은 의미로 실행되는 Preview:** 동일한 저장 소스를 실제 검증/컴파일/모의 실행기에
   전달하고 Node/Edge trace와 실패 이유를 되돌린다. 게시 전후 버전도 추적한다.
4. **지속 운영과 유지보수:** 상주 실행·원 작업·복구·자원 인계와 운영 화면을 연결하고,
   검증된 조합을 Linux 패키지로 제공한다. 실제 장비 적용은 별도 입회·자격 근거까지 확인한다.

현재 R7 정산 작업은 4의 기반으로 계속 필요하다. 그러나 이를 이유로 1–3의 사용자 경험을 계속
뒤로 미루지 않는다. 신규 내부 기능의 보고에는 연결된 화면/명령, 저장된 결과, 미완 경계를 함께 제시한다.

첫 대표 수락 시나리오는 **Task 선택 → 물체·현장 자원/대상 그룹 선택 → 값과 출처 확인 → 로봇 후보와
제외 이유 확인 → 오류 수정 → 저장/재열기 → 같은 버전의 모의 실행 trace 확인**이다.
이 시나리오 하나의 성공은 모든 기능·장비·현장의 완료를 뜻하지 않는다.

## 나머지 기능 초안과 ROBOTIS 기본 지원

2026-10-01 추가 확인: 사용자는 나머지 기능도 모두 초안 수준까지 완성하고, 기존 지시대로
ROBOTIS 플랫폼 로봇을 기본 이용할 수 있는 framework를 요구했다. WF01–WF17 중 쉬운 화면만
완료하고 나머지를 목표 밖으로 빼지 않는다. 각 기능의 실제 저장·검증·지원되는 실행/모의 경로와
미지원/오류/복구 표시를 갖춘 전체 초안을 목표로 한다.

PG07의 기본 번들은 RX Client Libraries, DYNAMIXEL SDK, DYNAMIXEL Hardware Interface,
AI Worker, AI Sapiens, OpenMANIPULATOR 및 필요한 의존성·어댑터·프로파일·예제다.
기본 이용 가능의 수락 조건은 다음과 같다.

- 설치 패키지에 선정 버전과 필수 실행 의존성이 포함되고, 설치·버전·자산 상태를 확인할 수 있다.
- 사용자가 로봇/기능 카탈로그에서 선택하면 해당 Task·Capability·Skill 구현·연결 설정·예제가 연결된다.
- 지원하는 모의 실행을 재현할 수 있고, 실제 연결에는 확인한 제어 인터페이스와 현장 설정을 사용한다.
- 시작·중지·관측·원 요청 조회·장애·복귀를 운영 화면에서 구분해 추적한다.
- 설치됨, 어댑터 연결됨, 모의 검증됨, 실물 검증됨을 별도로 표시한다. 미설정 제어 제공자나
