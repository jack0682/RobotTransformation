# RX 제품 초안 마일스톤과 첫 개발 스텝

기준일: 2026-10-07. 사용자가 이 대화에서 정한 M0–M7을 내재화하고 문서화하도록 요청했다.
이 문서는 **재구성 종료 후 제품 초안 개발의 수락 순서와 기준**이다. 계획 기록이며 구현·시험·사용자 수락 완료 선언이 아니다.
이번 요청은 문서화와 기억 보존이다. 재구성 종료를 선언하거나 제품 구현, 기존 실패 Run 재실행, 릴리스, 물리 운전을 시작하지 않는다.

## 1. 목표와 계획의 관계

> 재홍님이 RX 액션 그래프에서 작업·부품·환경·장비를 선택하고 필요한 조건을 설정해,
> 거의 코딩 없이 열처리 업무를 구성·검증·모의 실행·변경·복구할 수 있는 제품 초안을 완성한다.

- 액션 그래프가 주 작업 공간이다. Task 라이브러리, 정의와 설정, 값의 출처, 장비 적합성, 오류 위치, 실행 결과를 같은 작업 문맥에서 연결한다.
- 이미 지원하는 기능을 조합하는 일반 작업에서는 코드·JSON·YAML 수동 편집이나 내부 권한·실행 ID 조작을 요구하지 않는다. 새 능력과 장비 연동의 개발은 별도 작성자 역할이며, 결과는 다음 사용자가 재사용한다.
- 현재 상주 코어 초안을 출발점으로 삼는다. 그 판단은 전체 신뢰성·운영 복귀·배포가 완성됐다는 뜻이 아니다.
- [Workflow 기능 WF01–WF17](46_workflow_product_experience.md), 참조 HTML의 전체 기능, [상주 요구 RF01–RF14](implementation/resident_framework_completion.md), PG07 기본 번들과 기존 품질 게이트를 유지한다. 작은 성공 사례로 전체 범위를 대체하지 않는다.
- [마스터 플랜](42_framework_master_plan.md)의 과거 Phase/버전 표와 [세부 계획 W00–W24](implementation/framework_delivery_plan.md)는 설계·작업 분해의 입력이다. 재구성 후 사용자에게 결과를 전달하는 순서는 이 문서를 따른다. 기존 작업 번호를 완료 처리하거나 삭제하지 않는다.
- 이 문서의 ID는 **DRAFT-M0–DRAFT-M7**이다. 대화에서는 M0–M7로 줄여 부른다. 저장소 이전의 M0–M8이나 과거 세부 계획의 M번호와 별개다. 이전 작업의 PASS를 이 문서로 승계하지 않는다.

## 2. 사용자가 확인한 정상 반복 사이클

대상은 양쪽에 그리퍼가 달린 듀얼 그리퍼와 별도의 회전 정렬 장비를 사용하는 열처리 공정이다.
설명상 신규 소재 측을 A, 기존 가공품 측을 B라고 부른다. 실제 장비 채널명은 아직 지정하지 않는다.

1. 신규 소재 준비 확인 → A로 파지 → 파지 상태 확인 → 회전선반에 안착.
2. D405 홈 검출 → **회전선반이 소재를 회전 정렬** → 정렬 완료·정지 확인 → **고정된 자세로 재파지** → FT 착좌 확인.
3. 장비 앞 대기 → 가공 완료 확인 → 도어 개방 → 로봇 진입.
4. 빈 B로 기존 가공품 파지 → 착좌 확인 → 지그 해제 → 인출.
5. 듀얼 그리퍼 방향 전환 → 신규 소재 삽입·착좌 확인 → 지그 고정 → A 파지 해제.
6. 로봇 후퇴 → 도어 닫힘 확인.
7. **CNC 가공 시작과 기존 가공품의 완성품 트레이 적재를 병행**한다. 적재 뒤 다음 소재 준비·정렬을 수행한다.
8. **다음 소재 준비 완료와 현재 가공 완료가 모두 충족되면** 다음 교환을 시작한다.

선반의 회전 정렬과 듀얼 그리퍼 방향 전환은 다른 작업이다. 신규 소재와 기존 가공품, 두 파지 채널의 점유를 각각 추적한다.
빈 설비의 첫 투입, 마지막 회수, 실패 복구는 별도 시나리오로 정의한다. 실패 문서의 제안 처리를 이 정상 흐름 승인으로 자동 확정하지 않는다.
실제 주소·좌표·힘·속도·시간 제한·관측 신호는 확인 전 값을 추정하지 않는다. 모의값은 SIMULATION으로 명시한다.

## 3. 마일스톤

| ID | 목표 | 사용자에게 보이는 결과와 수락 조건 |

| DRAFT-M6 | 여러 운영 영역의 협업 | 독립 영역 간 정상 인계, 단절 중 사전 승인된 제한적 로컬 수행, 재연결 정산을 검증한다. 두 영역과 세 번째 영역 연쇄, 분리 Linux 호스트 전송을 확인한다. |

**중간 도착점:** M2는 전체 정상 공정 시연, M4는 우리 공정의 모의 운영과 복귀, M7은 전체 소프트웨어 초안 RC다.
실물 운전·현장 적격·기능 안전·도시 규모 성능 검증과 BT 자동생성 연구는 후속이다. RF14는 별도 미완 요구로 남긴다.

이 순서는 사용자 수락 순서이며 모든 구현의 엄격한 직렬 순서를 뜻하지 않는다. 실행 결함이 M1/M2를 막으면 그 결함부터 처리한다.
실패·UNKNOWN 보존은 M1부터 적용하며 M4까지 미루지 않는다. M4에서는 전체 복귀 시나리오를 수락한다.
외부 어댑터 CP2·CP3와 배포 검증의 기존 미결은 필요한 단계의 선행 조건으로 연결한다. 이 계획은 기존 Run의 정산·해제·재시도나 변경된 부하 조건의 수락을 대신하지 않는다.

## 4. 첫 개발 스텝: 소재 정렬·재파지

2026-10-07 밤의 DRAFT-M0–M1 실행 범위는 [정밀 실행 계획](implementation/draft_m0_m1_execution_plan.md)을 따른다.
그 문서는 기술적 구현·검증·인계와 M1 사용자 수락을 분리하며, M2 이후 착수를 허용하지 않는다.

### 재구성 직후 첫 착수 작업

다음 수락 장면을 현재 코드에 대응시키는 **짧은 연결표**부터 작성하고 곧바로 M1 구현 작업으로 사용한다.
표의 열은 `사용자 단계 / 기존 화면·API·실행 기능 / 빠진 연결 / 수정 대상 / 확인 방법`이다.
새 전체 아키텍처 문서를 반복 작성하는 단계로 늘리지 않는다. 아직 제품 구현에는 착수하지 않았다.

### 사용자가 수행할 장면

**라이브러리에서 소재 정렬·재파지 추가 → 부품·장비 선택 → 필요한 값과 출처 확인 → 저장·재열기 → 모의 실행 → 그래프에서 결과 확인.**

| 항목 | M1에서 고정할 내용 |
|---|---|
| 대상 | 정렬할 소재의 신원과 정의 버전 |
| 자원 | 회전선반, D405, 로봇, 듀얼 그리퍼 신규 소재 측, FT 센서 |
| 세부 흐름 | 선반 안착 → 홈 검출 → 선반 회전 정렬 → 완료·정지 확인 → 고정 자세 재파지 → 착좌 확인 |
| 결과 | 지정 소재가 정렬된 상태로 지정 파지 채널에 파지됐다는 확인과 근거 |
| 사용자 설정 | 부품·장비 참조와 필요한 현장값. 실행 ID와 내부 권한은 시스템이 처리 |
| 확인된 실패 | 예: 홈 미검출. 실패 위치·이유·잔여 소재 위치/점유를 표시 |
| 결과 불명 | 예: 응답 유실. 원 호출을 조회하며 실행을 자동 반복하지 않음 |
| 미정 사항 | 실제 신호·좌표·힘·시간, 정렬 완료·정지의 확인 방법. 시험에는 명시적 모의 provider와 값 사용 |

### M1 완료 조건

1. 사용자가 코드나 JSON을 편집하지 않고 필요한 대상을 설정한다.
2. 저장·재열기 후 같은 정의·설정 버전이 유지된다.
3. 화면에서 만든 구성이 기존 RX 검증·실행 경로로 전달된다. UI 전용 실행기나 예시 성공값으로 대체하지 않는다.
4. 정상 결과가 원 Task와 세부 동작·대상·실행 기록에 연결되어 표시된다.
5. 홈 미검출 같은 확인된 실패와 응답 유실에 따른 결과 불명을 구분하고 잔여 책임을 보존한다.
6. 재홍님이 직접 같은 과정을 수행하고 결과를 확인한 뒤 수락한다.

기존 기능이 있으면 연결한다. 없는 공통 의미만 반례·영향을 확인해 확장하고, 시나리오 값·순서를 공통 코어에 하드코딩하지 않는다.

## 5. 기존 요구의 배정

주 수락 단계를 배정한 표이며 세부 기능 삭제나 완료 판정이 아니다. M0에서 구현·증거 단위 연결을 보완한다.
M5는 참조 HTML의 전체 기능 누락을 다시 대조하고 M7은 통합된 설치판에서 재확인한다.

| 요구 | 주 수락 단계 |
|---|---|
| WF01 목록·버전, WF02 라이브러리·캔버스 | M1, M3, M5 |
| WF03 포트·전이, WF04 분기·병렬·대기·반복·Call | M2, M4, M5 |
| WF05 Task 계약, WF06 Object, WF07 Resource, WF08 대상 그룹, WF09 속성·출처 | M1, M3, M5 |
| WF10 제약, WF11 Capability·Skill·후보 | M3, M5 |
| WF12 인계 | M2, M4, M5, M6 |
| WF13 실패정책, WF14 검증·오류 이동, WF15 Preview·trace, WF16 게시·운영 | M1부터 연결, M4–M7에서 전체 수락 |
| WF17 싱글/듀얼·툴링 | M2, M3 |
| RF01 공통 모델, RF02 등록·실행, RF03 자원 묶음, RF04 의존·관측, RF05 작업 계약 | M0–M2의 필요 연결, M4–M5의 전체 수락 |
| RF06 교체·제거, RF07 복귀, RF08 upgrade/restore, RF10 지속 운영 | M4, M7 |
| RF09 열린 확장, RF11 표준 번들, PG07 | M5, M7 |
| RF12 품질·재사용·비용 | 단계별 축적, M7 종합 |
| RF13 영역 간 협업 | M6, M7 |
| RF14 물리 게이트 | 소프트웨어 RC로 닫지 않는 별도 후속 미완 |

PG07은 RX 클라이언트 라이브러리, DYNAMIXEL SDK, DYNAMIXEL Hardware Interface, AI Worker, AI Sapiens, OpenMANIPULATOR 및 필수 의존성·어댑터·프로파일·예제다. 일개미·집개미는 범위 밖이다.
기존 30개 불변식 의미 시험, 속성 시험, 10k seed, 결함 주입 행렬, 처리량·24시간 soak, 이기종 두 계열·두 번째 사이트 재사용과 C1–C5 측정을 유지한다. 상세 기준은 기존 전체 계획을 따른다.

## 6. 완료 판정과 진행 기록

- 각 작업은 문제·요구 ID·기존 연결점·수정 범위·사용자 결과·정상/실패 시험을 갖는다.
- 구현 완료, 실행 검증, 사용자 수락을 분리한다. 새 마일스톤은 이 문서만으로 진행/완료 상태가 되지 않는다.
- 완료 근거에는 소스 revision, 정의/Workflow 버전, 재현 방법, 화면·저장·실행 결과, 실패 결과와 지원 한계를 연결한다.
- 코드량·시험 개수·문서량·CI green만으로 완료율을 만들지 않는다. 사용자가 수행할 수 있는 시나리오로 보고한다.
- 첫 작성 시간, 변경량, 직접 작성한 코드/설정과 명령 수, 진단·복구 시간, 원 개발자 개입을 측정한다. M1 실제 소요를 확인한 뒤 후속 일정을 산정한다.
