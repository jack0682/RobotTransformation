# 오늘 밤 DRAFT-M0–M1 실행 계획

작성일: 2026-10-07 KST. 범위: [제품 초안 마일스톤](../48_draft_product_milestones.md)의 DRAFT-M0과 DRAFT-M1만.
상태: **실행 지시 준비 문서. 이 문서 작성으로 구현·시험·사용자 수락을 완료 처리하지 않는다.**

## 1. 목표와 종료점

> 재구성된 개발 기준선을 확인하고, 소재 정렬·재파지 Task를 사용자가 화면에서 선택·설정·저장·재열기한 뒤,
> 기존 RX 경로에서 모의 실행하고 같은 그래프에서 결과를 확인할 수 있는 M1 수락 후보를 만든다.

오늘 밤의 기술적 산출물은 **M0 검증 기록 + M1 실제 실행 검증 + 사용자가 따라 할 인계**다.
M1 마일스톤의 최종 완료에는 사용자의 직접 수락이 필요하다. 사용자가 부재하면 `USER_ACCEPTANCE_PENDING`으로 인계하고 M2를 시작하지 않는다.
에이전트 goal을 사용한다면 목표를 이 기술적 인계까지로 명시한다. goal 종료와 M1 사용자 수락을 같은 것으로 표시하지 않는다.

사용자가 시각·시간·토큰 상한을 별도로 지정하지 않았으므로 이전 migration의 시간 예산을 상속하거나 마감 시각을 임의로 만들지 않는다.
명시된 상한이 나중에 주어지면 그 전에 진행 기록을 남긴다. 시간 부족을 이유로 UI를 빼거나 모의 성공값으로 완료 조건을 축소하지 않는다.

## 2. 착수 조건과 작업 경계

### E0: 재구성 인계

1. `RobotTransformation`의 현재 AGENTS·CONTRIBUTING, 원격 develop SHA, 로컬 branch/status, 진행 중 작업의 파일 소유를 확인한다. Git 조회에는 `GIT_OPTIONAL_LOCKS=0`을 사용한다.
2. 재구성 담당자의 최신 인계에서 개발 원본·변경 종료 범위·남은 migration 작업을 읽는다. 과거 M0–M4 PASS를 새 DRAFT-M0 완료로 사용하지 않는다.
3. 재구성 작업이 같은 source/layout/CI를 수정 중이면 읽기 전용 M0 연결표를 먼저 작성한다. 인계 또는 명확히 분리된 작업 범위가 확인될 때까지 충돌하는 제품 변경은 시작하지 않는다.
4. 기존 로컬 문서 변경과 미추적 파일을 분류한다. `48_draft_product_milestones.md`와 이 실행 계획이 아직 커밋되지 않았을 수 있다. 새 worktree에 자동 포함된다고 가정하지 말고 필요한 계획 파일만 정확한 사본으로 가져와 차이를 기록한다.
5. `47_heat_treatment_exchange_scenario.md` 등 다른 작업의 초안은 보존한다. 그 실패 처리 제안을 사용자 승인으로 승격하지 않는다.

### E1: 실행 환경

- 보존 Mac에서 제품 cargo/docker/npm build·test, Docker 조작, dev server 기동을 하지 않는다. 정적 읽기·문서 검사·코드 편집은 가능하다.
- 기존에 허용된 격리 Linux runner/개발 환경을 사용한다. 환경의 OS/arch·CPU/메모리·source SHA·설치/image identity와 사용 범위를 기록한다.
- UI와 P/Executor/Host를 함께 검증할 수 있어야 한다. 브라우저 시험도 격리 환경에서 수행하고, 사용자 인계는 승인된 접근 경로나 재현 명령으로 제공한다. 공개 서버·방화벽·새 유료 자원을 임의 생성하지 않는다.
- 실행 환경이 없으면 가능한 정적 M0 작업을 완료한 뒤 부족한 환경을 명시한다. Mac에서 몰래 실행하거나 검증된 것처럼 표시하지 않는다.
- migration 배포 검증 전체(M5)를 오늘 밤의 선행 작업으로 자동 확대하지 않는다. M1에 필요한 정확한 실행 경로만 준비한다.

### 허용되는 제품 변경

기존 operator UI, 필요한 application/API 연결, 생성 SDK, Task/모의 adapter·scenario package, 해당 시험·검증 자료를 수정할 수 있다.
기존 의미 안에서 필요한 최소 공통 결함 수정은 M1 요구와 변경 이유를 기록한 뒤 수행한다. 코어 전면 재작성·리팩터링으로 확대하지 않는다.
규범·entry/completion·UNKNOWN·권한·freshness/deadline 의미나 호환성 변경이 불가피하면 원인·대안 하나·영향을 제시하고 해당 부분은 사용자 결정 전 진행하지 않는다.

### 제외 범위

- DRAFT-M2–M7의 전체 사이클, 범용 품목/트레이 편집, 싱글/듀얼 전환 UI, 다중 영역, 전체 번들, 24시간 soak, 정식 배포.
- 자연어 생성, 3D 물리 시뮬레이터, 별도 UI 실행 엔진, 새 권한/결과 DB.
- 과거 CP2 Run의 재시작·재발행·정산·자원 해제·부하 환경 변경. 기존 source/evidence/volumes는 읽기 전용이다.
- 실패 중인 성능/진단 후보 branch의 일괄 병합. M1에 필요하면 원인과 변경을 따로 대조한다.
- migration 재개, 원 저장소 수정·archive, main 승격, tag/release, 물리 장비 운전.

## 3. M0: 짧고 검증 가능한 기준선

산출물은 하나의 `M0_BASELINE.md`다. 저장소 밖 작업 폴더 또는 승인된 증거 위치에 작성하고 최종 검증 기록에서 참조한다.
새 프레임워크 설계서를 반복 작성하지 않는다. 다음 표를 실제 읽은 source/API/test로 채운다.

| 사용자 단계 | 조사 시작점(현재 존재하는 경로, 지원 완료 보증 아님) | M0에서 답할 질문 |

각 행에 `기존 기능 / 빠진 연결 / 수정 파일 / 검증 방법 / 지원 한계`를 추가한다. M0 안에서 위 source를 필요한 깊이만큼 추적한다.
기존 `workflow-resolution`의 빈 `property_sets`/`inputs`, 구조형 v1 그래프와 새 workflow model의 분리는 조사 단서다. 재확인 없이 이미 해결됐거나 구현 불가능하다고 단정하지 않는다.

M0 기록에 포함할 항목:

- remote/local SHA, 후보 branch/worktree, 필요한 계획 문서의 전달 상태.
- 재구성 인계·파일 소유·격리 Linux 환경·브라우저 접근 경로.
- 기존 성공 증거와 실행하지 않은 부분. 기존 F1 수락과 CP2 미수락을 구분.
- M1 package/definition/workflow/operation 신원의 연결도와 필요한 수정 범위.
- T01–T10의 구체 실행 명령/시험 위치/기대 결과. 명령은 현재 도구의 도움말·소스에서 확인한다.

**M0 통과:** 현재 기준선과 실행 환경이 확인되고, M1의 각 사용자 단계에 기존 연결점 또는 필요한 변경·시험이 배정된다.
이 조건을 충족하면 별도 계획 재승인을 기다리지 않고 허용된 M1 구현으로 진행한다. unresolved 계약/환경/소유 충돌만 의존 작업의 차단 사유다.

## 4. M1 Task의 최소 계약

### 시작과 끝

- 시작: 식별된 신규 소재를 신규 소재 측 그리퍼가 보유하고, 정렬 Task를 요청할 수 있는 모의 초기 조건이다.
- 끝: 같은 소재가 정렬된 상태로 같은 지정 파지 채널에 재파지됐고 착좌 확인이 있다. 선반 점유의 종료도 모의 provider의 근거와 연결한다.
- 기존 가공품 인출, 듀얼 방향 전환, CNC 가공, 트레이 적재는 이번 Task 밖이다. 양쪽 그리퍼 구조는 표현하되 다른 채널을 사용하는 전체 교환을 구현하지 않는다.

### 표현할 동작과 확인

| 순서 | 동작/확인 | 의미와 관측 |
|---|---|---|
| A1 | 회전선반으로 이동·안착 | 지정 소재와 선반을 연결하고 소재 지지/위치가 바뀌는 시점을 기록 |
| A2 | D405 홈 검출 | 같은 소재의 방향 관측 또는 명시적 미검출 결과. 실물 카메라 근거로 표현하지 않음 |
| A3 | 회전선반 회전 정렬 | 검출 결과를 소비해 선반이 회전. 로봇 손목 회전으로 대체하지 않음 |
| A4 | 정렬 완료·정지 확인 | 현재 소재·선반에 맞는 근거 확인 뒤 재파지 허용 |
| A5 | 고정 자세로 재파지 | 지정 로봇·신규 소재 측 그리퍼를 사용 |
| A6 | FT 착좌 확인 | 같은 소재/파지 채널의 결과 근거로 Task 완료 판단 |

안착 후 개방·지지 전환과 재파지 때의 세부 동작은 모의 profile에 명시한다. 실제 물리 방식이 확인됐다고 가정하지 않는다.
기존 계약의 시작/완료/조회 의미를 재사용하며 이 표가 새 wire 상태기계를 정의하지 않는다.

### 입력과 결과

UI에서 선택할 것은 소재 모델/대상, 로봇, 신규 소재 측 파지 채널, 회전선반, 비전·FT 기능과 해당 모의 설정이다.
정의/패키지의 불변 참조, 값·단위·출처, 기존 사용 조건을 그대로 유지한다. 실제 주소·힘·속도·좌표·deadline을 추정하지 않는다.
모의 기본값을 미리 제공할 수 있으나 사용자 선택이 실행 입력에 반영돼야 한다. 다른 부품 또는 허용된 모의 값 변경 하나로 이를 확인한다. 전체 M3 편집 기능은 만들지 않는다.

모의 provider는 독립적으로 호출·상태·결과 기록을 남긴다. P/Host 기록에서 효과 수를 계산해 같은 주장의 독립 근거라고 사용하지 않는다.
브라우저 타이머, fixture 응답만 반환하는 UI mock, P 원장 직접 수정은 종단 실행의 증거가 아니다.

## 5. 구현 순서와 관문

| 체크포인트 | 수행 | 다음으로 넘어갈 조건 |
|---|---|---|
| C0 | E0/E1와 M0 연결표 | 기준선·실행 환경·수정 범위·시험 확보 |
| C1 | 기존 package/definition으로 M1 Task와 모의 조건 연결 | 서버가 입력·출처·revision을 검사하고 기존 runtime에서 정상 Task 수행 가능 |
| C2 | 액션 그래프의 Task 선택·설정·저장·재열기 | 사용자 JSON 편집 없이 같은 revision을 다시 열고 오류 위치를 확인 |
| C3 | UI 실행과 실제 P/Executor/Host 결과 연결 | 화면에서 만든 버전의 실행/효과가 대응하며 새로고침 후 결과 추적 |
| C4 | 알려진 실패·결과 불명·회귀 검증 | 아래 T01–T10의 적용 항목 통과; 한계/제외 항목은 근거와 함께 명시 |
| C5 | 변경 검토·사용자 인계 | 현재 후보와 증거 일치, 실제 클릭 순서와 접근/재현 경로 제공; M1 수락은 사용자에게 남김 |

C1의 CLI/API 실행 성공만으로 M1을 완료하지 않는다. C2의 화면 성공만으로 C3 실행을 대체하지 않는다.
단일 작업 branch를 기본으로 한다. 필요한 worktree는 현재 앱의 관리 도구를 사용하고, 다른 작업의 미커밋 파일을 가져오거나 원 checkout을 전환하지 않는다.
작업 branch의 서명·DCO 커밋 및 develop 대상 PR은 저장소 절차를 따른다. PR을 만들면 현재 채팅에 연결한다.
사용자가 별도로 승인한 merge 범위가 없다면 후보/PR과 증거로 인계한다. CI 또는 병합 자체는 사용자 수락이 아니다. main·tag·release는 대상 밖이다.

## 6. 검증 행렬

각 실행에 source SHA, 환경/arch, 정의·Workflow revision, request/operation ID, 실제 결과와 근거 위치를 남긴다.
아래는 실행 계획이며 PASS 기록이 아니다. 모두 격리된 모의 설치에서 수행한다.

| ID | 확인할 장면 | 기대 결과 |
|---|---|---|
| T01 | 라이브러리에서 Task 추가·대상/장비 설정·저장·재열기 | 직접 JSON 편집 없음, 같은 definition/workflow revision과 선택값 유지 |
| T02 | 필수 대상 누락 또는 잘못된 타입·단위/참조 | 해당 설정 위치에 오류, 실행 시작/모의 효과 없음. 초기 fixture 문제를 제품 오류로 오인하지 않음 |
| T03 | UI 정상 실행 A1–A6 | 원 Task와 step·operation·provider 기록 대응. 선반 회전/고정 자세 재파지를 별도 표시하고 완료 근거 확인 |
| T04 | 허용된 모의 설정 또는 소재 선택 하나 변경 | 새로 검토한 입력이 실제 provider 호출에 반영되고 이전 저장 버전은 불변 |
| T05 | 실제 provider가 홈 미검출을 보고 | 확인된 실패로 표시. 회전·재파지로 진행하지 않고 소재/선반의 남은 점유를 숨기지 않음 |
| T06 | native 진입 뒤 완료 증거 수신을 차단 | 기존 의미에 따라 UNKNOWN과 원 ID/자원 보존. 후속 효과·중복 명령 없음. 브라우저 응답 유실과 구분 |
| T07 | UI 요청/응답 유실 후 원 요청 조회·새로고침 | 새 ID로 재실행하지 않고 원 기록 표시. 완료된 실제 요청의 추가 효과 없음 |
| T08 | 새 정의 버전 또는 다른 내용의 동일 요청 제출 | 기존 pin/원 요청 보호. 실제 효과 전에 거절해야 하는 경로에서 효과 없음 |
| T09 | 변경 범위의 기존 회귀·계약/SDK·문서 검사 | 실제 적용 시험의 성공과 skipped/미실행을 분리. 필요한 경우 정확한 후보의 전체 CI 수행 |
| T10 | 브라우저 실제 왕복과 인계 재현 | UI/API/runtime을 함께 사용하는 브라우저 시험, 화면 캡처, console/network 오류 확인, 실제 클릭 순서·접근 경로 확보 |

T06은 M1의 불명 표시·보존 시험이다. 동일 증거 조회로 회복 가능한 경우도 표시할 수 있지만,
adapter kill/restart 전체 CP3, 관리자 전체 상실 복구나 일반 M4 운영 복귀를 완료했다고 확장하지 않는다.
불명인 시험 실행을 다음 시험을 위해 강제 해제하지 않는다. 시험별 별도 설치/ID를 준비하고 이전 불명 상태를 보존한다.
UI mock 시험은 빠른 회귀용으로 사용할 수 있으나 T03/T10은 실제 서버/실행 경로에서 수행한다.
외부 네트워크/장치 없이도 모의 provider의 실제 명령 수신과 결과 기록을 관측해야 한다.

## 7. 실패·범위 통제

- 실패하면 원 명령·rc·후보 SHA·입력·최초 오류·실행 범위를 보존하고 원인을 좁힌다. 같은 불변 후보를 이유 없이 반복 실행해 green만 선택하지 않는다.
- 이전에 실패했던 후보는 수정 diff와 실제 관련 회귀를 확인한 뒤 재검증한다. 시간 제한 확대, 검사 제거, UNKNOWN을 실패/성공으로 변경해서 통과시키지 않는다.
- M1 경로를 실제로 막는 기존 결함은 최소 수정 대상으로 삼는다. 인접 결함·일반 최적화·M2 이후 요구는 기존 parking에 요구/근거/영향만 기록한다.
- 격리 실행 환경 부재, 재구성 파일 소유 충돌, 불가피한 계약 의미 변경은 의존 작업을 멈추고 정확한 차단점과 권장 다음 조치 하나를 보고한다. 독립적인 허용 작업은 계속한다.
- goal 상태는 실행 환경의 규칙을 따른다. 사용자의 pause 없이 임의 paused 처리하지 않고, blocked 임계 조건을 지키며, 준비되지 않은 결과를 complete로 표시하지 않는다.
- 원 CP2의 부하·Run·자원 보존은 별개다. 새 격리 M1 성공을 CP2 수락이나 성능 문제 해결이라고 쓰지 않는다.

## 8. 산출물과 인계

불필요한 문서 증식을 피하고 아래 세 문서와 필요한 원시 시험 산출물만 남긴다. 경로는 M0에서 확정한다.

| 산출물 | 필수 내용 |
|---|---|
| `M0_BASELINE.md` | 인계·source·환경·기존/누락 연결표·변경 범위·시험 실행 방법 |
| `M1_VALIDATION.md` | C1–C5와 T01–T10 실제 결과, 실행/검증/사용자 수락 구분, 실패 이력, 원시 근거 링크 |
| `M1_TRY_IT.md` | 정확한 후보/환경, 검증한 접근 또는 시작 명령, 클릭 순서, 정상·실패·불명 예상 표시, 종료/재열기, 보존 상태 |

진행 보고는 `현재 체크포인트 / 새로 가능한 사용자 행동 / 방금 확인한 근거 / 남은 차단점 / 다음 한 가지`로 간결하게 한다.
실제 기동한 서비스가 있으면 소유·접근·정지 방법을 기록한다. 실패/UNKNOWN 증거를 지우기 위한 정리나 자동 reset은 하지 않는다.
최종 보고에는 diff/branch/PR, 실제 검사, 사용자가 실행할 경로, 미검증·미완 범위를 포함한다. 사용자가 부재하면 기술적 인계 완료와 M1 사용자 수락 대기를 분리한다.

## 9. 이번 문서 작성 시 확인한 출발점

이 절은 계획 작성 당시의 참고이며 실행 에이전트가 다시 확인한다.
개발 원본은 RobotTransformation이고 기존 48번 문서와 관련 navigation 변경은 로컬 미커밋 상태다.
재구성 인계 기록은 R3 진행 중이며, 원 CP2 미수락·외부 어댑터 진단 후보 실패·배포 검증 보류가 남아 있다.
