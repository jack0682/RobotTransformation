# 02. 개인 프로젝트의 가치와 평가 기준

기준일: 2026-09-14 · [최상위 목표](01_product_definition.md)는 사용자 확정. 아래 가치 가설과 지표는 검증을 위한 제안이며 측정 결과나 수치 약속이 아니다.

## 1. 만들려는 가치

RX가 제공하려는 가치는 **서로 다른 로봇과 시설을 연결해 하나의 일을 끝까지 수행하고, 참여자와 서비스가 늘어도 운영 규칙과 개발 자산을 재사용할 수 있게 하는 것**이다.

안전한 실행, 효율적인 협업, 장애 후 복귀 가능성, 새 참여자의 연결 비용을 함께 평가한다. 결과 불명을 정확하게 보존하는 능력과 실제 작업을 완료하는 능력을 각각 측정한다.

## 2. 역할별 기대 효과

| 역할 | 해결하려는 문제 | 검증할 변화 |
|---|---|---|
| 서비스 이용자 | 여러 로봇·시설에 걸친 요청의 진행과 완료를 알기 어려움 | 전체 작업의 진행·지연·인계·완료 추적 |
| 로봇·시설 운영자 | 자원 경합과 다른 운영 영역의 작업 조정 | 책임·권한·점유·인계 조건의 명확성 |
| 서비스 개발자 | 장비마다 실행·실패·복구를 다시 구현 | 기존 작업 계약과 기능을 조합하는 범위 |
| 장비 연동 개발자 | 지원 능력과 제약을 상위 서비스에 전달 | 능력·관측·중단·복구 조건의 일관된 선언 |
| 프로젝트 개발자 | 범용화 효과와 복잡성 증가를 판단 | 사례별 변경량·검증 비용·운영 성과 비교 |

## 3. 평가 원칙

서로 다른 장비·서비스·공간으로 확장할 때 기존 코어와 계약을 얼마나 유지할 수 있는지 확인한다. 파일 수나 코드량 자체를 성숙도의 지표로 삼지 않는다. 성능과 신뢰성은 지원 조합·부하·장애 조건·관측 기간을 함께 기록한다.

거부·중단·불명·사람 개입을 집계에서 제외해 완료율을 높이지 않는다. 안전 관련 평가는 시험에서 관측한 범위와 실제 현장의 보호 책임을 구분한다.

## 4. 제안 지표

| 평가 축 | 측정할 것 | 함께 기록할 조건 |
|---|---|---|
| 전체 작업 완료 | 제출 요청 중 최종 조건을 만족한 비율, 완료 시간 분포 | 거부·취소·불명·진행 중 요청, 관측 종료 시점 |
| 자동 수행 | 전체 요청 중 비정상 사람 개입 없이 완료한 비율 | 예정된 사람의 수령과 복구 개입을 분리 |
| 협업 효율 | 처리량, 작업·공유 자원 대기, 이동량·에너지 | 같은 작업량·장비·공간·정책의 비교 기준 |
| 권한과 인계 | 중복 실행, 동시 점유 충돌, 미확인 인계 사건 | 주입한 장애와 검출·차단 범위, 미확인 물리 상태 |
| 복구 가능성 | 장애 감지부터 책임·자원 확인과 운영 복귀까지의 시간 | 자동 조정·사람 조치·장비 대기를 분리 |
| 결과 불명 | 미결 수·지속시간·해결 근거와 장기 미해결 비율 | UNKNOWN을 성공·실패로 임의 변환하지 않음 |
| 이기종 연결 비용 | 새 장비의 연동·설정·시험 공수와 공통 계층 변경량 | 실제 능력 차이·추가 센서·제어기 제약 |
| 서비스 조합성 | 새 작업에 재사용한 기능·계약과 필요한 새 구현 | 같은 이름의 기능이 동일 의미인지 확인 |
| 규모 확장 | 참여자·동시 작업·영역 증가에 따른 지연·처리량·저장·통신 비용 | 하드웨어·네트워크·시간 조건과 장애 영향 범위 |

[선언·판정 지원도 측정](21_declaration_reuse_measurement.md#6-두-번째-기준선-조사-현재-결과)은 규범의 77자리를 declared 4와 free 73으로 분류하고 RX 전용 선언 포장 부담 하한을 4로 기록했다. 채워진 비교 기준선이 없어 inherited는 측정 불가다. 이 수치는 시간·비용 절감의 실측이 아니다.

수치 목표는 아직 미정이다. 최소 검증 시나리오의 기준값을 측정한 뒤 후속 목표를 정한다. 작업 차단이 늘었다는 사실만으로 안전성과 가용성이 함께 개선됐다고 판단하지 않는다.

## 5. 생태계 확장의 판단 기준

새 장비를 연결할 때 지원 능력·조건·버전·검증 범위를 선언할 수 있어야 한다. 새 서비스는 검증한 작업을 가능한 범위에서 조합하고, 추가 의미가 필요하면 공통 계약의 변경 이유를 설명할 수 있어야 한다.

플러그인 수나 참여 회사 수는 현재 확보한 생태계 규모를 뜻하지 않는다. 세 저장소는 공개되어 있다. 프로젝트 원본은 Apache License 2.0으로 공개하며 제품 배포·외부 참여 운영 방식은 별도 미결이다.

## 6. 기존 사업 지표의 위치

인건비 절감, 납품 기여이익, 견적·지원 SLA와 고객 인수는 이전 산업 자동화 사례의 평가 기준으로 남긴다. 해당 사례를 수행할 때 사용할 수 있지만 개인 프로젝트 전체의 최상위 성공 기준으로 삼지 않는다.

기존 원문과 계산 조건은 [전환 전 사업 가치 문서](https://github.com/jack0682/rx_docs/blob/6111a7d1dcf33052f38c3e67c6585aec2b44df3c/docs/02_value_and_business.md)에 보존했다. 사업화 여부와 방식은 이번 전환에서 확정하지 않았다.
